# Zotero corpus workflow (local only)

This skill accepts references to local outputs generated by external Zotero/corpus workflows.

## Input boundaries

- `init` accepts `--snapshot-path` and `--snapshot-digest`.
- The snapshot may be in an independent private directory outside the network
  root. It must be an absolute, regular, non-symlink local file.
- No direct Zotero API calls or library writes.
- `ingest-zotero-snapshot` accepts `--snapshot` only after it is bound via `init`.

## Snapshot binding

1. On init, open the absolute path with no-follow/nonblocking flags, verify a
   regular-file descriptor, and compare device, inode, size, mtime, and ctime
   before and after the read.
2. Compute file SHA-256 from the same bytes used to parse JSON; reject
   read-time drift rather than reopening the path.
3. Recompute producer `identity_sha256` from group ID, collection key, and the
   `{key,name}` projection of collection path. Recompute `state_sha256` from
   identity, collection version, and parents with canonical JSON.
4. Interpret `--snapshot-digest` as producer `state_sha256`; users do not need
   to calculate a file hash. Store the automatically computed file digest as
   `corpus_snapshot_file_sha256` and state digest separately.
5. Store only the absolute source path and digests in `network.json`; do not
   copy the curation snapshot into the network.
6. Re-run the stable read during `validate`; either state or file mismatch is
   fail-closed.

## Snapshot ingest (bulk source import)

- `ingest-zotero-snapshot` supports only:
  - `schema: ZoteroCorpusSnapshot/v1`
  - absolute, non-symlink local path
- Initial and non-refresh ingest require the canonical command path to match the
  bound path. `--allow-refresh` may use a new absolute producer output path
  because producer writes are exclusive-create; identity must remain unchanged.
- Producer `state_sha256` must equal `corpus_snapshot_digest`. The consumer
  computes the file SHA itself and binds it as `corpus_snapshot_file_sha256`.
- `identity_sha256` is recomputed from group/collection identity and must match
  both the declared value and the network binding.
- `state_sha256` is recomputed from identity, collection version, and parents;
  its declared value and bound value must match.
- Imported rows are metadata-only parents:
  - no note/PDF contents are dereferenced
  - `read_depth` is always `metadata`
  - `role` is always `zotero_corpus`
  - idempotent by source_id/payload
  - all records are written in deterministic canonical parent order
- The entire batch is preflighted and staged as complete files. Handled commit
  failures restore prior bytes. Multi-file replacement is not process-crash
  atomic: a prepared `.transaction.json` journal survives interruption and
  blocks validation/mutation. Version 1 has no automatic recovery command;
  inspect target digests and recover the prior or staged generation before
  clearing the journal.

## Refresh

- Default ingest rejects any file or state drift.
- `--allow-refresh` is valid only after the initial snapshot was ingested.
- `identity_sha256` must still match the binding and `state_sha256` must change.
  The source path may change; successful refresh updates the current binding and
  records previous/new paths and digests in the refresh event.
- Unchanged parents remain current without new ledger rows.
- Changed parents append a deterministic source revision with `supersedes`.
- A matched changed revision counts as `changed`, not `added` or `removed`;
  `removed` means no current parent matched the prior current identity/key.
- Added parents append new rows. Removed parents remain in history but are
  excluded from `corpus_snapshot_current_source_ids` and status.
- A `snapshot_refreshed` event records added, existing, removed, and current
  counts, with changed parents reported separately from added parents.

## Corpus-safe behavior

- Never ingest from remote/network sources.
- Never dereference symlinks for snapshot and ledger files.
- Allow absolute snapshot inputs outside the network root; they are read-only
  corpus inputs, not generated artifacts.
- Reject symlink snapshot paths for `ingest-zotero-snapshot`.
- Keep every state, ledger, internal snapshot, and export output inside the
  network root.
