# Bounded primary-source investigation

Use this route for a finite technical fact cluster or when handing a bounded
research branch to a worker. A broader academic comparison or evidence map
still uses the core loop and its specialist owners.

## Match work to the question

For a small documentation, specification, or source-version check, inspect the
relevant primary artifacts in the controller. Delegate when the branch can run
independently while the controller does useful work, or needs a distinct tool
context. Follow the host's delegation and tool policies; a research label alone
does not justify parallel searches of the same source.

Choose the owner of the fact: specifications for normative behavior, released
documentation for supported interfaces, commit-bound source for implementation,
and observed runtime evidence for executed behavior. Match the requested
version and status; issue proposals and roadmaps do not establish release.
Search snippets and secondary accounts are discovery aids, not the final source.
For an academic candidate search use `$scholar-discovery`; for one selected
paper's meaning use `$learn-from-papers`. Index metadata can identify a paper,
but cannot establish its scientific claims.

## Compact branch brief

Use the existing action or worker card, with only the fields needed for this
branch. This is a human-readable handoff, not a new machine schema:

```text
question or gap, intended use, and acceptance criteria
scope and version/date bounds
allowed sources and execution permissions
existing source/query/action IDs and inherited budget
requested output and authorized workspace, if any
specialist owner artifacts required for the downstream stage
stop condition and what to return if access or budget fails
```

Assign one source or query lineage and separate draft output to each worker;
keep shared ledger, search-history, and network writes with the coordinating
owner. Specialist execution authorization and replay requirements still apply.
The worker cannot approve another source domain, enlarge scope, declare a stage
complete, or turn its own narration into independent review.

## Cited findings view

Lead with the bounded answer. For each consequential fact include the source
identity and version, a precise section/page/line locator, the applicable
condition, and whether the evidence supports, qualifies, contradicts, or leaves
the fact unresolved. Separate source statements from inference. Report failed
access and unresolved disagreements instead of smoothing them into certainty.

If a readable note is requested or needed in an authorized durable workspace,
write one concise Markdown note per branch at the requested destination or the
repository's existing notes location. Preserve existing files and conventions;
otherwise choose a clear location and report it. When no durable write is
authorized or needed, return the same findings in the worker card or response.
Use local links for private artifacts and omit them from public projections.

For academic branches, the note links the owner's candidate/search results or
paper artifacts; it does not replace their typed outputs, source inspections,
coverage records, validation, approval, or downstream acceptance.

## Return and accept

The controller inspects the returned source identities, locators, qualifiers,
failures, and required artifact bindings before using the findings. Reopen the
relevant source regions when necessary to assess a consequential claim; avoid
duplicating the entire branch without a specific evidence gap.

A finite artifact check stops after its promised facts and applicable checks
are satisfied, or ends with explicit unresolved facts when access or budget
prevents closure. It does not need unrelated search rounds and cannot claim
systematic coverage, citation-audit closure, or pragmatic saturation from a
short note. Broader targeted research retains its countercheck closure and
stopping rules; governed reports retain their required citation audit.
