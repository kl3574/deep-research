# v0.6.0 release notes

Evidence cutoff: 2026-08-05

`v0.6.0` is a real-scenario hardening release for the auditable research skill
suite. The driving case was a compound DoE and surrogate-model investigation
over an existing Zotero corpus. The release claim is bounded to the artifacts
and tests below; it does not claim systematic-review completeness, successful
Google Scholar browser automation, or successful activation of every
experimental Zotero component.

## Package scope

The default Codex install contains nine orthogonal skills:

1. `deep-research`
2. `learn-from-papers`
3. `research-knowledge-network`
4. `network-gap-discovery`
5. `scholar-discovery`
6. `scholarly-source-acquisition`
7. `scholarly-document-normalization`
8. `curate-research-to-zotero`
9. `research-network-publish`

The repository also contains `zotero-declarative-bridge` version `0.1.1` as an
**experimental, runtime-blocked companion**. It is intentionally excluded from
the default Codex installation set. Its offline protocol tests are useful
development evidence, but they do not prove that Zotero loaded the plugin or
that any mutation occurred.

## Evidence-backed changes from the DoE run

### Scenario control and search

- Added the immutable compound `ResearchScenario/v1` pipeline and an explicit
  `source_normalization` stage between acquisition and paper understanding.
- Replaced raw structural gap names as search input with competency-question-
  backed semantic topic needs. This change was prompted by real off-topic API
  results from metadata-only gap placeholders.
- Preserved provider, query, pagination, exclusion, failure and manual-route
  provenance. Google Scholar remains a user-supplied export route; official
  scholarly APIs are the autonomous route.

### Source acquisition and document quality

- Added `scholarly-source-acquisition` for one explicitly selected public PDF,
  with public-origin/redirect checks, PDF identity, size and SHA-256 validation,
  bounded wall-clock execution and partial-file cleanup.
- A live fetch exposed a timeout that exceeded its nominal deadline and left a
  `.part` file. The implementation now uses a monotonic total deadline, socket
  shutdown and bounded cleanup. Loopback proxy transport is explicit opt-in and
  accepts no credentials or remote proxy.
- Added `scholarly-document-normalization`. The real corpus contained both
  pathological extracted text and a blank scan; the resulting OCR derivatives
  preserve original/derivative hashes, tool versions and argv lineage, remain
  `review_required`, and make no OCR-accuracy claim.

### Deep reading, evidence and network publication

- Three real deep-reading batches independently rechecked 24/24, 21/21 and
  28/28 final bounded claims after initially overbroad claims were narrowed.
- The existing-corpus semantic projection produced 54 atomic claims, 8 explicit
  conflicts and 12 gap candidates from 28 parent records. These are bounded
  run observations, not universal coverage statistics.
- Added `research-network-publish` to render a validated immutable network and
  optional research map as deterministic, self-contained HTML. Public mode
  rejects absolute paths, private item keys, content hashes, note bodies, full
  text and credentials.

### Zotero curation contracts

- Metadata-only notes now have a machine-readable schema-9 projection:
  `data-access-level="metadata_only"`, visible `全文状态：未获取全文`, map depth,
  and dated metadata provenance. They contain no PDF/full-text hash, arbitrary
  64-hex content hash, or claim-table data row.
- Full-text legacy notes and `PaperKnowledgeNote/v2` retain the verified-PDF and
  64-lowercase-hex full-text SHA contract. The batch verifier dispatches legacy
  11-section notes, five-section `PaperKnowledgeNote/v2`, and metadata-only
  notes by explicit root contract and rejects mixed markers/layouts.
- The native importer compares bundle `access_level`, the root marker and the
  shared validator projection. It no longer accepts a metadata-only note solely
  because a Chinese regular expression happens to find a missing-text phrase.

### Ledger recovery

- Every mutating research-ledger command now records append-only
  `commands.jsonl` start/finish receipts with pre/post event count and digest,
  committed/partial state, one-command batch context and an explicit recovery
  plan.
- A real partial-commit simulation preserved the successfully appended fact,
  detected a conflicting blind retry, and recovered derived caches through
  `resume` without claiming rollback.

## Known limitations and blocked delivery

### Google Scholar browser route

The real run started the browser bridge, but the Google Scholar browser
extension did not connect. No Scholar result page was read, no CAPTCHA was
bypassed, and API results were not relabelled as Scholar results. Scholar
coverage therefore remains `not_provided_manual_optional` unless the user
provides a dated export. This is a disclosed provider limitation, not silent
fallback success.

### Zotero declarative bridge

`zotero-declarative-bridge` `0.1.1` passed offline Python and JavaScript protocol
tests. Zotero `9.0.6` rejected the packed plugin at the loader boundary. The
plugin was not registry-active, no authenticated probe or preview succeeded,
and **zero Zotero writes** were performed through it. Its release status is:

```text
experimental
runtime_status: blocked_loader_rejected
activated: false
writes: 0
default_codex_install: false
```

Do not advertise collection membership, note mutation or attachment repair via
this bridge as available until a compatible Zotero loader accepts it and the
capability/probe/preview/apply/readback sequence passes on a disposable fixture.

### Unrepaired Zotero state

- Eleven existing attachment records remain unrepaired in Zotero. Verified
  replacement bytes or offline manifests are not write/readback evidence.
- Three existing-parent collection-membership/note operations remain unapplied.
- The release therefore must not claim that the original Zotero delivery request
  completed. Research status and delivery status remain separate.

## Migration notes

### Research pipeline

Executions created before `source_normalization` have the exact legacy
nine-stage shape. `validate` now returns `migration_required`; it does not
silently reinterpret that state. Preserve the old file and create a new one:

```bash
python skills/deep-research/scripts/research_pipeline.py migrate \
  --input /private/pipeline-04.json \
  --as-of 2026-08-05T13:00:00Z \
  --output /private/pipeline-05-migrated.json
```

Migration reopens every bound artifact, verifies path/size/SHA-256, preserves
legacy history and inserts `source_normalization` as pending with reason
`normalization evidence required`. Use `--inserted-status blocked` only when
normalization evidence cannot currently be produced. Never overwrite the old
execution or mark normalization complete without a validated quality/lineage
artifact.

### Research ledger

The v1 fact ledgers remain canonical; `commands.jsonl` is an append-only command
observability journal, not a replacement fact log. There is no destructive
ledger rewrite step. Preserve the whole run directory, then inspect it with:

```bash
python skills/deep-research/scripts/research_run.py \
  --root /approved/research-workspace \
  --run-id RUN_ID \
  status
```

If status reports an interrupted or partial command, follow its machine-readable
recovery plan and run `resume`; do not delete JSONL rows or blindly repeat a
mutation. `resume` repairs derived caches and records recovery, but never claims
that an already committed fact was rolled back. Run `validate` and refresh the
coverage audit before finalization after any substantive recovery event.

### Metadata-only notes

Do not satisfy the old full-text SHA requirement with a placeholder hash. Update
the note to the explicit metadata-only root marker, visible disclosure, empty
claim-table body and metadata provenance, then rebuild the bundle note hash and
rerun importer/batch dry-run. Existing valid full-text and
`PaperKnowledgeNote/v2` notes require no marker migration.
